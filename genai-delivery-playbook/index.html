What I built

Most GenAI projects fail on the same things: the wrong use case, retrieval that leaks documents across permissions, and releases with no evidence of quality or safety. This project follows one IT-support copilot through every phase of delivery, and each phase is backed by code.

A scoring tool ranks candidate use cases on value, feasibility, risk and data readiness, and rejects any that fail a governance check. In the copilot, documents keep their access labels through ingestion, and the access filter runs inside the search call, so the same question gets a different answer for an employee than for someone in finance. Guardrails block direct and indirect prompt injection and redact personal data. Output must be valid JSON citing only retrieved sources. Every model call goes through a gateway that enforces token quotas, falls back to a second model, tracks cost, and writes a redacted audit log.

The release gate runs 18 normal questions and 15 attacks and checks six metrics against agreed thresholds. The test model is deliberately naive: it leaks its prompt and obeys hidden instructions. Switch the guardrails off and the gate fails, which is itself an automated test.

Highlights

  • Per-user access control that fails closed: no labels or no identity means no documents
  • Indirect-injection screening tested with a planted, poisoned knowledge-base article
  • Evaluation gate in CI alongside SAST, secret and IaC scanning
  • Azure Terraform with private endpoints, managed identity and no API keys
